# Sover backlog — self-expanding social-media executive (vision roadmap)

Ordered, single-increment, gated steps from a fresh chat-only executive outward. Reuse the shipped capability/scaffold/discovery/rebuild machinery; never reinvent.

- [ ] HONESTY FIX (prerequisite, no new powers): Rewrite pi/CONTROL.md and pi/SYSTEM.md to describe the ACTUAL tool-less + bounded-action surface — delete the false 'kimi-k2.7-code with read/edit/write/bash tools / edits dashboards / runs jobs' claims and state the real propose-only/whitelisted-action menu. Gate: a test asserting neither doc contains the strings 'read/edit/write/bash' (or equivalent tool claims) and that CONTROL.md names only the verbs the runtime actually executes.
- [ ] CHAT READ-CONTEXT (pure read, no actions): Inject a compact STATE block into the chat system prompt — profile.json brand/niche/voice/handles/status, onboarding state, latest followers from account_history, pending proposals, monetization plan from monetization_gate.run(). Edit scripts/api/routes/chat.py only. Gate: a test that the assembled chat prompt contains the live profile id, status, and current follower number from a fixture profile (so the executive answers with real numbers, never hallucinated).
- [ ] CHAT ACTION PARSER (reuse run_pi's pattern): Add _execute_chat_actions(reply) to chat.py that extracts a fenced ```json {"actions":[...]} block and dispatches the SAME whitelisted verbs run_pi._execute_cgo_actions already supports — propose -> proposals.propose, need -> needs.flag — and nothing else yet. Each action best-effort + try/except-isolated; never posts/spends/edits. Gate: tests that a reply with a propose action files exactly one proposal and that an unknown action type is ignored without raising.
- [ ] CHAT CAN TRIGGER ONBOARDING (#1 gap, reuse existing endpoint): Add an 'onboard' verb to _execute_chat_actions that calls onboarding.start() (the existing detached _onboard_run flow) behind the existing X-Operator-Confirm gate. First delightful win: 'learn my brand' -> ingest+synthesize -> draft proposal. Gate: a test that the onboard verb invokes onboarding.start for the active profile and is refused without the operator-confirm header.
- [ ] GENESIS API (the missing creation entrypoint): Add POST /sover/profiles/create (X-Operator-Confirm) and a small sover_profile.create(id, brand) that atomically writes profiles/<id>/ (status=draft, minimal profile.json + placeholder SOUL.md) and appends a registry.json row using the EXISTING atomic _write_json + load.cache_clear() pattern. A new profile boots chat-only, everything else locked. Gate: tests that create() registers the profile, sets status=draft, is idempotent on an existing id, and respects single-writer/atomic-write.
- [ ] SCAFFOLD ACTION ON THE BRAIN (first real caller of scaffold()): Add a 'scaffold' action type to run_pi._execute_cgo_actions that calls capabilities.scaffold(cap_id, manifest, files) with status forced to 'proposed' — the brain emits route.py/lane.py/panel.html bodies as STRINGS, never touching bash/file tools. compile()-check each emitted file before write; reject on SyntaxError. Gate: tests that a scaffold action writes capabilities/<id>/ at status=proposed, files a kind=capability proposal, and that a syntactically-broken body is rejected without writing.
- [ ] SCAFFOLD ACTION ON THE CHAT (executive earns its first surface): Add the same 'scaffold' verb to _execute_chat_actions, restricted to cloning vetted templates (start from example_pulse's shape — a panel.html + read-only /cap/<id>/state route, requires_rebuild=false). The executive can now add a SURFACE to itself, operator-approved. Gate: a test that the chat scaffold verb produces a discoverable proposed capability whose code compiles and whose template matches the allowed set.
- [ ] CAPABILITY TEMPLATE LIBRARY + LINT (codegen safety): Add capabilities/_templates/ with vetted RESEARCH/COMPOSE/MEASURE/PANEL templates and a capabilities.lint(files) that runs compile() + forbids imports of master.post / money paths / frozen_guard-protected modules. Wire lint into scaffold() so authoring is template-fill, not arbitrary codegen. Gate: tests that lint passes the templates, rejects a lane importing master.post, and rejects a route shadowing a core path.
- [ ] DECIDE -> REBUILD END-TO-END (prove the loaded gun, no new path): Wire capabilities.decide(approve) (already returns requires_rebuild) so that an operator approval of a requires_rebuild=false capability goes live on next discovery with NO rebuild (dev STATE_ROOT==repo), and only requires_rebuild=true triggers rebuild_relaunch_exe, rate-limited and operator-gated. Gate: a test that a decided requires_rebuild=false capability is picked up by capabilities.routers_for()/lane_specs() and one asserting rebuild is NOT invoked for it.
- [ ] FIRST RESEARCH CAPABILITY niche_radar (read-only, real growth signal): The executive scaffolds capabilities/niche_radar/ — a lane.py that CDP-scrapes the profile's own niche hashtags/competitors (reuse onboarding.py's IG ingest harness) into data/<id>/niche_signals.json, plus a panel.html. Parents: chat + onboarding. Unlocks COMPOSE nodes. Gate: a test that niche_radar's lane.run() writes only under data/<id>/, returns a summary string, and touches no posting/money path.
- [ ] GROWTH PLANNER NODE growth_scout (the supervisor proposes the next move): Add a growth_scout capability/lane that reads supervisor.gather_state() + capabilities.all_caps() + the static capability TREE (parent edges defined per node, NOT brain-chosen) and each cadence emits ONE proposal: the lowest-cost frontier node whose parents are all 'active', ranked by expected follower/engagement leverage, surfaced via capabilities.set_focus(). Gate: tests that growth_scout proposes only parent-satisfied nodes, never fabricates an unlock edge, and emits at most one proposal per cadence.
- [ ] MONETIZATION GRADIENT (money becomes the score, stays human-gated): Re-anchor growth_scout/brain ranking so the leverage score = how much a node shrinks 'days to next LOCKED monetization stream' from monetization_gate.run(). Seed per-profile data/<id>/monetization_stages.json at onboarding accept from a brand-tuned default. No new action types; reuse the gate. Gate: a test that with a near-threshold fixture, growth_scout prioritizes the node that closes the nearest monetization gap.
- [ ] OFFER-ASSEMBLER CAPABILITY (autonomous creative runway, one human click): When the gate moves a stream to READY_APPROVAL, the executive scaffolds capabilities/offer_builder/ whose lane assembles a sign-ready package (affiliate: candidate programs + FTC disclosure + posts to attach; digital_product: brief + price + draft listing) and files needs.flag(kind='money') with the package — passing brand_safety.py. The irreversible enroll/accept/connect-payout stays a single operator record_decision. Gate: tests that offer_builder only fires on READY_APPROVAL, every artifact passes brand_safety, and no code path calls enroll/pay (assert record_decision is a pure ledger write).
- [ ] ATTRIBUTION + RETIREMENT (the tree becomes measurable): Add attribution_radar — a read-only lane joining post_registry to account_history deltas to write per-capability fitness, so each capability node carries a number proving it earned followers/engagement. Feed it to growth_scout so a losing capability is proposed for decide(disabled). Gate: tests that attribution_radar computes per-cap fitness from fixtures and that growth_scout proposes disabling a capability whose fitness is below a floor.
- [ ] CAPABILITY-AUTHORING CAPABILITY (meta frontier, fully self-directed): The executive scaffolds a capability whose subagent.md + lane.py author NEW capability code from the template library when growth_scout detects an unmet, parent-satisfied need with no existing template (e.g. comments full of 'where do you buy this' -> a link-in-bio/storefront capability). 'If it can't be done yet, the agent BUILDS the ability' becomes real — still proposed-only, lint-gated, operator-approved, rebuilt. Gate: tests that the authored capability passes lint, ships only via decide(), and never auto-activates.
